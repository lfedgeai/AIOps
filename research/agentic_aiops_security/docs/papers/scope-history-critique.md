*O'Neill Joseph. Working paper, November 2026. Companion to "The Logic of Scope-and-History Agentic Security." The question is which conclusions are not yet entailed. Empirical tests are left for later.*

## Abstract

Scope & History-Aware Agentic Security is a wrapper around SPIFFE/SPIRE for context attacks: direct prompt injection, indirect prompt injection, context hacking, and temporal reuse of memory or commission. The saved note fixes several breaks in the earlier argument. The minted prompt is bound by a public check value. Context, tool calling, tool cache, memory, and indices are cleared together. Discovery reports live in a memory the workloads do not share. A cold-start agent is fingerprinted in the sandbox. The monitor treats anything outside the local baseline as anomalous, and it also names an attempt to reach a new resource. The sandbox cannot exfiltrate. A helper is requested again only for equal or reduced scope. The Recorder stands between a finished report and the stores the next task will read.

This paper grants those repairs and the reconstruction in the companion paper [@validation]. It also grants the later ones. The best-guess workflow is added to the first user prompt of a newly minted agent, and the note says it is not the system prompt, so a synthesis of other workloads cannot enter the check value. That first task is the fingerprint. The drift result the Recorder already computed for the work-order report is forwarded to the workload host. The run becomes the base run when the work stayed inside organizational policy and guidance and the agent adhered to its system prompt. A wrong answer inside the system prompt is a reasonable fault and can enter that baseline. Exfiltrating the source database leaves the system prompt, including when a user prompt asked for it, and it is withheld. The check value shows the system prompt was not replaced. Adherence shows the result stayed inside it. Initial user prompts pass input guardrails, and the orchestrator's plan passes output guardrails, so a request or a plan that leaves the duty fails before an agent is assigned. The brief is closed by the author's rule. A session chain is audited before a report is added to memory. A chain read as dangerous is stopped, and its reports are isolated and quarantined. They are not the next brief. The redo of a failed report uses bonded agents, and only then. Each is read-only and one-shot, the whole prompt including the delegated prompt is hashed, and a synchronous publication reaches only the nodes that produced the failure, before dispatch. A bonded report that shows the same fault is kept for forensics and is never added to memory. If the workflow cannot continue without that report, it fails. The wrapper claim still does not follow from the text at one joint. The monitor can transfer a validated workload when it sees an attempt, which does not entail that the attempt missed the resource. A cold start reconciles the shards of an indirect injection after validating the profile, which is a different object from those shards, so an instruction fetched at a vendor boundary can still be written at the core before the report is quarantined. The clock is closed by the author's rule. A revocation forces a Bellman publication. Unused agents carry a countdown on that list, a later list that still includes the agent resets the countdown, and SPIRE issues a token only when the remaining countdown is longer than the token and a resetting publication comes before the countdown expires. Fifteen minutes of countdown against a list thirty minutes away is a refusal. Forty-five minutes against a resetting list in thirty is an issuance. Direct injection is the class the check value, the input guardrail, and adherence already cover. Context hacking is contained when the next brief and the discovery memory are behind the Recorder. Until that joint is closed, an injection carried home is not yet shown to miss the primary store. Quarantine withholds the report. It does not unwind a shard the profile check already reconciled.

## 1. What is granted

The check-value step is valid as an integrity check. Hashing the presented system prompt and comparing it to the published value fails exactly when the formulation was replaced. SPIFFE/SPIRE remains the identity and location layer [@spiffe; @spire]. The five gateway questions are the right list for the conclusion the note wants. The sandbox's keepalive rule entails that the sandbox itself is not an exfiltration path. Clearing context, tool calling, tool cache, memory, and indices entails that the warm agent does not carry the previous task forward in those stores. Every cold-start agent's first task runs in the sandbox, and that task is the fingerprint. The fingerprint is the starting point of the reputation entry. The score the workload host receives is the drift result the Recorder already computed, forwarded rather than recomputed. The comparison is to organizational policy and guidance, and it requires adherence to the system prompt. A misidentification inside that prompt passes. An exfiltration fails, including when the user prompt requested it, and only a pass sets the entry as the base run. The baseline is accumulated over a series of runs. The best-guess addendum is the first user prompt and is excluded from the system prompt, so it cannot change the published formulation. It is also an initial user prompt, so a synthesis that leaves the duty fails the input guardrail and does not run. The orchestrator's plan fails its output guardrail when the plan leaves the duty. A remembered helper is eligible again only at equal or reduced scope, which is the subset relation the deputy argument needs [@hardy1988]. None of these points depends on how often a detector is right.

The companion paper lists twelve assumptions under which the rest of the conclusion follows. This paper asks which of those assumptions are not supplied by the note. An architecture can leave a premise for later specification. It cannot treat the conclusion as already derived while the premise is missing.

## 2. Grain is a rule for the minter, and the best guess is a different text

Separation of privilege entails that one injected page cannot both fetch at the internet boundary and write in the core when those are separate conditions, held apart [@saltzer1975]. The note now states the split as a dispatch rule. The orchestrator produces a granular plan from discovery, and a policy-as-code pass revises it until it complies or the turn limit is reached. The dispatcher prefers existing single-job agents over minting one agent that crosses every trust boundary, and a new mint is cut along those boundaries under least privilege. When that rule is followed, the fetch and the core write are different profiles, and the gateway's fourth question can refuse the cross-boundary action because the profile does not contain it [@byun2005].

The gateway does not apply the rule. It hashes the prompt it is given and honors that profile. A mint that ignored the grain rule produces a check value for the wide prompt, and every later check succeeds for it. The preference and the boundary rule are instructions to the same component that mints. They are not a second condition that fails a wide mint. The boundary split follows from the dispatcher complying. It does not follow from the rest of the chain correcting the dispatcher.

The best-guess addendum does not reopen that joint. The note places it on the first user prompt and excludes it from the system prompt. The check value binds the system prompt alone. A synthesis of several workloads cannot become the formulation, and fingerprinting cannot publish a widened check value.

What the exclusion does not settle is the user prompt itself. It is still chosen from similar earlier workloads or synthesized from several. Similarity is the relation the note has withdrawn for helper reuse. The two database tools are the case that shows why: they share tooling and differ in scope. A synthesis that treats them as one workflow can brief the narrow agent with the wide one. The system prompt stays narrow. The first task does not.

That brief runs while the local list may not yet contain the new profile, which is why the cold start is in the sandbox. Promotion then requires the updated list and a validated profile and scope. The object validated is the profile. The object that produced the shards is the synthesized user prompt. The note's own distinction between those texts means a check of one does not entail a check of the other. The companion paper's third assumption supplies the missing link: the synthesis stays inside the minted profile, and the shards are reconciled only when they do. The note states the exclusion. It does not state that link. Equal-or-reduced scope governs helper reuse. It is not stated as the rule for this synthesis. A synthesis that leaves the duty now fails the input guardrail and does not become the fingerprint prompt. Section 5 takes up what the guardrails do not see. Data retrieved after the plan is issued are not an initial user prompt and are not the orchestrator's output. A departure that arrives there can still have its shards reconciled by a check of the profile alone.

## 3. Transfer to the sandbox does not entail that the action was contained

There are two entries to the sandbox, and they are not the same inference.

If the profile is unconfirmed, or the behavior is not in the reputation database, the agent starts in the sandbox. Writes are shards. Nothing is reconciled until validation. Nothing is exfiltrated except a keepalive. For that entry, containment precedes effect. The inference holds.

If the agent has already passed the five questions, it is an approved workload. The monitoring client then watches. Anomalous behavior, or an attempt to access a new resource, can move the workload into the sandbox. Naming the attempt is a real tightening: the event can be the request for a resource the baseline does not contain, which is the HR read and the cross-duty resource case, rather than only a completed effect. The response is still optional, and it is a transfer of the workload. An attempt that the resource has already answered is not undone by moving the agent afterward.

The companion paper's fourth assumption repairs this by placing the monitor on the path, so the attempt is held and then contained. That is a coherent design. History-based checks that change rights do so at the decision, not after the effect [@abadi2003; @park2004]. The text says the workload can be transferred. It does not say the attempt is refused. Until that is the rule, the note has shown how to contain work that was never approved, and how to notice an attempt by work that was. It has not shown that the attempt itself fails.

## 4. Validating the initiating prompt does not validate the effects

For a recognized agent whose behavior changed, the gateway asks the dispatcher to validate the initiating workload prompt, and then reconciles the shards. Two gaps sit between that sentence and the conclusion that only the assigned task reaches the primary database.

The first gap is the object of the check. The initiating prompt is the text that started the work. Indirect prompt injection leaves that text alone and rides in data the agent was allowed to read [@greshake2023]. The prompt validates. The shards can still be the mass delete. Nothing in the note says the shards are compared to the prompt, or that they are a determined consequence of it. Promotion of an unchecked effect does not inherit the truth of a check performed on a different object. The companion paper's sixth assumption states the missing link. The note does not.

The second gap is who performs the check. The dispatcher wrote the plan and the context brief, under the user's credential and least privilege. Asking the dispatcher to validate the initiating prompt can mean two things. It can mean a comparison against the minted profile, which is an independent predicate and which would do the work the architecture needs. Or it can mean confirmation that this prompt is one the dispatcher issued, which is true by construction and adds no premise. A check that returns to the author of the object is not a second condition in the sense separation of privilege requires [@saltzer1975]. The note says "validate" and does not say against which standard.

Coercion makes the second reading especially empty. The syndicate's success condition is that a real user request, from a real employee, asks for the wrong duty. The dispatcher that accepts the request and the dispatcher that validates the prompt are the same step seen twice. The profile at the gateway is the independent standard. The note sends the behavioral case to the dispatcher instead.

## 5. Drift is policy and adherence to the system prompt

The Recorder withholds a report that leaves organizational policy and guidance, that leaves the system prompt, that still contains restricted information, or that fails guardrails. The drift result is the comparison the work-order report already requires. It is forwarded to the workload host for the initial reputation entry. There is no second evaluation, and the comparison does not ask whether the data are correct. A model that calls a dog a kangaroo and asserts it has made a reasonable fault inside the system prompt. The report stands, and a cold-start run of that kind can be the base run. The same agent exfiltrating the source database has left the system prompt. That result is withheld from the report and from the base run.

Adherence and the check value are different claims. The check value fails when the system prompt was replaced. Adherence fails when the result left the system prompt that was checked. The input and output guardrails sit in front of both. A request to exfiltrate fails before the orchestrator plans it. A plan that adds the exfiltration, or that widens the narrow delete into the bulk delete, fails before the dispatcher assigns it. A best-guess synthesis that imports another duty fails as an initial user prompt and never becomes the run the sandbox fingerprints. The standard is the duty. A wrong identification inside the duty passes here, as it does at the Recorder.

The single-report guardrail is aimed at direct injection. Indirect prompt injection arrives in data the agent was allowed to read [@greshake2023]. That data is not the initial user prompt, and it is not the plan the output guardrail checked. The agent can still be pulled off the system prompt after a clean front door. Adherence then withholds the report and the base run.

A legitimate request whose danger arrives later is the chain audit's case. The supply-chain report is an in-duty prompt. The input guardrail passes. The plan that assigns the fetch passes the policy engine. The result can still contain an instruction from the page that was read. If the agent follows that instruction and leaves the system prompt, adherence fails and the report is rejected. If the agent files the instruction inside an otherwise in-policy report, drift can pass on that report alone. The session chain is audited before the next report is added to memory. A chain read as dangerous is stopped, and its reports are isolated and quarantined. They are not the next brief. The note names a simple classifier as the reader of the sequence. The entailment used here is the withhold attached to a dangerous reading. It is not a measurement of that reader. The dispatcher redoes the workload. The redo that returns to the nodes which produced the failure uses bonded agents. They are read-only. Their reports are checked for the same fault. A report that shows it is kept for forensics and is never added to memory. If the workflow cannot continue without that report, it fails, the user is told, and the failure is logged. Avoiding the source is the claim. An investigation that blacklists the resource is outside the note.

The two admissions stay independent in one place. Profile validation reconciles the shards of the first task. Quarantine withholds the report from memory. An exfiltration fails the report. A wrong answer inside the system prompt fails neither, which is the intended outcome. A first task that left the system prompt can still reach the primary store on the profile check alone. Withholding the report does not withhold its shards.

The admitted report is the context brief of the repeated task. The wipe of context, tool calling, tool cache, memory, and indices closes the agent's private residue. It also removes every competing memory, so the admitted report is the task's past. A quarantined report is not that past. The chain audit is the gate in front of the memory the next task reads. Discovery memory is a different store, and workloads do not write it.

Decommissioning is a forced publication, not a wait for the next scheduled list. A revocation triggers the Bellman protocol because it is volatile. The list also carries a countdown for unused agents, and a later list that still includes an agent resets that countdown. SPIRE issues a workload token only when the remaining countdown is longer than the token's lifetime and a publication that resets the countdown occurs before the countdown expires. An agent fifteen minutes from decommission, with the next scheduled list thirty minutes away, receives no token: the countdown ends first, and a token issued now would outlive the agent the list is about to drop. An agent forty-five minutes from decommission, with a list in thirty minutes that resets the countdown, can receive a token. The node that detected the injection can also refuse locally at once. The delay that a purely periodic broadcast would have left on the other nodes is not part of this rule.

## 6. Helper reuse now has the right relation

A helper with stricter limits than the caller, minted as its own agent and refused at the boundary if it would leave, blocks the confused deputy when the helper's profile is a subset of the caller's authority for this task [@hardy1988]. The note now states the reuse condition in that form. A later task receives that helper only when its scope is equal or reduced. A wider later task does not inherit the helper. The earlier conflict between similarity and subset is withdrawn for subcontracts.

What remains is the comparison's input. Equal or reduced is a relation between scopes the architecture already mints. If the dispatcher compares those profiles, the inference holds. If it compares descriptions of the tasks, a description can call two duties the same scope. That is the grain problem of Section 2 applied to reuse, and the gateway still enforces the helper's own check value either way. The open joint is no longer the selection rule, and it is no longer the check value. A best-guess synthesis that leaves the duty fails the input guardrail and is not the prompt the sandbox fingerprints. A synthesis the guardrail accepts is one it read as the same duty. That reading is the grain question again.

## 7. The wrapper claim still needs the effect on the store

The claim under test is the wrapper, not a kill chain. SPIFFE/SPIRE remains who and where. The wrapper is supposed to stop a direct injection from replacing the system prompt, an indirect injection from becoming core context, a hacked brief from outliving its task, and a commission or a memory from being used after its time. Section 3 of the companion paper states that shape [@validation].

Direct injection is the class the architecture now covers. The check value fails a replaced system prompt. The input guardrail, the policy revision, and the Recorder's direct-injection check see the request, the plan, and the finished report. Adherence fails a result that left the system prompt.

Context hacking through the brief is covered. The chain is audited before a report is added to memory. A dangerous chain is quarantined. A bonded report that shows the same fault is never added. The wipe removes the agent's own residue. Discovery memory is separate.

The temporal class is covered by the countdown rule. A revocation forces a Bellman publication. SPIRE withholds a token that would outlive the published countdown, and it withholds a token when that countdown expires before the next publication can reset it. A bonded agent is a further case of the same clock: its check value is published to the relevant nodes before it is dispatched, and a later publication removes it when the report is in.

The open joint is the effect on the primary store. An instruction in a retrieved page is not the initial user prompt. The profile can validate, and the shards of what that instruction did can still reconcile. The monitor can transfer the workload after the attempt. Quarantine then withholds the report. It does not reach back into a shard the profile check already accepted. That joint decides whether an injection carried home misses the primary store. Closing it is a change to the connections among components. It is not a change to the vocabulary, and it is not a measurement.

## 8. Conclusion

The note now supports the wrapper's claim for the brief and for three of the four classes. The system prompt in use is the system prompt that was minted, so a direct injection does not replace it. A request or a plan that leaves the duty fails before an agent is assigned. A finished report that carries a direct injection is rejected, and the workload is redone. Discovery context is not the workload's memory. A warm agent does not keep its previous context, tools, cache, memory, or indices. A session chain read as dangerous is quarantined before it becomes the next brief, and a bonded report that shows the same fault is kept for forensics and is never added to memory. A workflow that cannot avoid that fault fails. A wrong answer inside the system prompt can become part of the baseline. A helper returns only for an equal or narrower scope. SPIFFE/SPIRE remains the identity and the node.

The indirect class is closed for the brief and open for the store. An injection in a page fetched beyond the organization's boundary does not become the next brief. The front door does not see that page. Adherence withholds a result that left the system prompt. The chain audit withholds a dangerous sequence that stayed inside the prompt. The temporal class is closed: a revocation forces a Bellman publication, and SPIRE does not issue a token that outlives the unused-agent countdown or that would be issued after the countdown has already beaten the next resetting publication. As specified, the monitor can transfer a workload after an attempt, and a cold start can reconcile shards after validating the profile alone. The wrapper would follow for the store if those connections were the ones the companion paper assumes. They do not follow from the connections the note has written down.
