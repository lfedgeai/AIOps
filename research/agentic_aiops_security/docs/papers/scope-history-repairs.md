*O'Neill Joseph. Working paper, November 2026. Companion to "The Logic of Scope-and-History Agentic Security" and "Where the Scope-and-History Argument Does Not Follow." The question is which connections make the critique's open joints follow. Every source cited here was published in 2017 or later. Empirical tests are left for later.*

## Abstract

Scope & History-Aware Agentic Security wraps SPIFFE/SPIRE for four context attacks: direct prompt injection, indirect prompt injection, context hacking, and temporal reuse of memory or commission [@validation]. The critique grants the direct class, the residue half of context hacking, the clock, and the brief [@critique]. A revocation forces a Bellman publication. Unused agents carry a countdown, and SPIRE issues a token only when that countdown outlasts the token and a resetting publication comes first. A session chain read as dangerous is quarantined before it is added to memory. The redo uses bonded agents, which are read-only and one-shot, and a bonded report that shows the same fault is never added to memory. It holds one joint for the rest. The monitor can transfer a workload after an attempt, which leaves the attempt itself unrefused. A cold start reconciles staged writes after the profile is validated, so an instruction fetched at a vendor boundary can still be written at the core before the report is quarantined.

This paper supplies the missing connection at the remaining joint, and it records the brief rule the note now states. A policy engine outside the dispatcher decides which profiles may be published, so one profile does not span the core and the internet. The monitor enforces that published policy: a tool call the policy forbids, including its arguments, is blocked before it runs. A call the policy permits that is still anomalous is sandboxed and sharded until a dry run shows the effects are not destructive or breaking. Reconcile then verifies those effects against a layout, and untrusted data cannot choose them. The next brief is the admitted report. A quarantined chain is not that report, and a bonded report that shows the same fault is kept for forensics. These are connections among components. They are not measurements of a detector.

## 1. The joints

The validation paper reconstructs the argument and lists the assumptions under which it is valid [@validation]. The critique grants the check value, the sandbox keepalive, the wipe, fingerprinting as the first task, equal-or-narrower helper reuse, the exclusion of the best-guess addendum from the system prompt, drift as policy plus adherence to the system prompt, and the two guardrails in front of the agent. It then names the places where the conclusion still asks for a premise the text does not contain.

One of those places decides the wrapper. An attempt by an already approved agent can be followed by a transfer of the workload, which limits a later action and leaves the attempt that revealed it. Staged writes reconcile when the profile and scope validate, so an instruction fetched across a trust boundary can reach the core on the strength of a check performed on a different object. Quarantine of the report does not unwind that write. A direct injection is already failed by the check value, the input guardrail, and adherence. Context hacking through the agent's own residue is already failed by the wipe. The brief is already a rule: a dangerous chain is quarantined before memory, the redo is a bonded read-only pass, and a report that shows the same fault is never added. The discovery memory, which the workloads cannot write, keeps a poisoned brief from becoming the plan. The clock is already a rule: revocation forces a Bellman publication, and SPIRE refuses a token that would outlive the unused-agent countdown or that would be issued when the countdown expires before the next resetting publication. A bonded agent's check value, which hashes the delegated prompt with the rest, is published to the nodes that produced the failure before that agent is dispatched, and a later publication removes it.

The chain audit is that admission for the brief. A session-tagged sequence is read before the next report is added to memory. A dangerous reading stops the workflow and quarantines the reports. The note names a simple classifier as that reader. The connection is the withhold, not the reader's rate.

The repairs below are the connections that were missing. Each one uses a mechanism published since 2017. None of them grades the data the agent produced. A misidentification inside the system prompt remains a reasonable fault.

## 2. Publication is a policy decision

The grain rule and the scope comparison fail for the same reason. Both are instructions to the dispatcher, and the gateway will honor the profile that was published. The repair moves the decision to an engine that is not the minter.

Cedar evaluates authorization policies outside the application that requested the action. An action is authorized only when a policy permits it. There is no default permit, and the decision does not depend on the order in which policies are considered [@cutler2024cedar]. Applied here, the dispatcher may propose a mint. Bellman publishes the profile only when the engine permits that proposal. A profile whose actions span two trust boundaries has no permit. The core write and the internet fetch are different permit rules. A prompt that means "the whole supply chain" matches none of them, so it never receives a check value. The gateway's later hash still does exactly what the validation paper says it does. It confirms that the prompt in use is the prompt that was published. The new connection is that a wide prompt is not among the prompts that can be published.

Separation of duties, in the control catalog, is enforced through access authorizations, not through the compliance of the person who holds a duty [@nist80053r5]. The dispatcher is the component that would otherwise hold both the proposal and the publication. The engine is the access authorization. A mint the dispatcher is inclined to make, and a mint the grain rule forbids, receive the same treatment: publication follows the permit.

Helper reuse uses the same store. Zanzibar decides authorization by evaluating relation tuples, and the decision is consistent with the order in which those relations changed [@pang2019zanzibar]. Equal or reduced scope is a relation between two published profiles. The dispatcher asks whether that relation holds. It does not decide by comparing descriptions of the tasks. A description that calls the narrow delete and the bulk delete the same job does not create the relation. The helper's own check value remains the gateway's test of which helper arrived. The relation is the test of whether that helper may be asked for.

## 3. Published policy blocks, and anomaly is quarantined

Zero trust places a policy enforcement point on the path of the request. That point enables the connection, watches it, and terminates it. The resource is not reached while the decision is open [@nist800207]. The policy it enforces is the published one. Progent applies that decision to a tool call before the call executes, arguments included. The procedure is deterministic. A call the published policy does not permit is blocked [@shi2025progent]. The two database tools that authentication cannot tell apart are different calls once the policy names the predicate. Deleting a malformed row as it arrives is permitted. Deleting thousands of drafts is a different argument, and the enforcement point blocks it before it runs. The block is the policy. It is not a judgment that the behavior looks unusual.

A call the published policy permits can still be anomalous. Anomaly, in the note, is anything outside the baseline of previous work, including an attempt to reach a resource the baseline does not contain. That call is not a policy violation, so the enforcement point does not block it. The monitoring client moves the workload into the sandbox, and the writes and deletes are recorded as shards. The primary store does not receive them.

The sandbox is the separate test environment in which a change is analyzed before it is implemented in the operational environment, including for intentional misuse [@nist80053r5]. The analysis here is a dry run of the shards. The dry run asks whether those effects are destructive or breaking: whether they destroy data or service beyond the permitted predicate. A misidentification inside the permitted call, such as calling a dog a kangaroo, is not destructive and is not breaking. A shard that copies out the source database, or that widens a permitted row delete into a bulk delete the policy did not name, fails the dry run and is not reconciled. A shard the dry run accepts may then be reconciled. Until that acceptance, the only outward message remains the keepalive.

## 4. Reconcile verifies the effects

A layout in in-toto names the steps of a supply chain, the functionaries allowed to perform each step, and the inspections the product must pass. The client accepts the artifact when the recorded metadata shows that those steps were performed by those functionaries and the inspections held [@intoto2019]. Identity of the functionary is one clause of that acceptance. The product is another. Applied to the sandbox, the profile check is the functionary clause. The shards are the product. The dry run in Section 3 is the inspection: the staged writes are the effects the layout allows for this profile, and they are not destructive or breaking. A bulk delete that the published policy already forbids never becomes a shard, because Section 3 blocks that call. A bulk delete that the policy did not explicitly forbid, but that the dry run finds destructive, fails the inspection and is not reconciled. The profile can be valid and the shards still refused. The two objects the critique separated are the two clauses of one acceptance.

Indirect prompt injection arrives in data the agent was allowed to read, after the input guardrail and the orchestrator's output guardrail have already passed. CaMeL keeps that data from becoming the control flow. The control flow is taken from the trusted query. Data retrieved afterward can supply values. It cannot choose the next step. When a tool is called, a capability policy is applied to the values that would flow into the call, which is what stops a value from being exfiltrated to a reader the policy does not allow [@debenedetti2025camel]. A step that retrieved text tries to add, such as copying the source database, is outside the trusted control flow. If the published policy forbids that call, Section 3 blocks it before it runs. If the policy does not explicitly forbid it and the call is only anomalous, the call is sharded, and the dry run withholds it because the effect is destructive. Adherence at the Recorder still withholds the report and the base run.

The two stores the dispatcher reads share that inspection. The Recorder produces one admission decision: the result stayed inside policy, adhered to the system prompt, carried no restricted fields, and its sharded effects passed the dry run. The context memory graph and the report database are written from that decision. A reader of either store is behind the same predicate. The next brief is that admitted report, as the validation paper already requires.

## 5. An instruction carried home is not the next brief

The supply-chain request is a legitimate task. The input guardrail passes. The plan that sends a fetch agent to the vendor boundary passes the policy engine. The page that comes back can contain an instruction. That instruction is an indirect prompt injection. It is also the start of a context hack if it is written into the shared brief, and the start of a temporal attack if that brief is still there on a later turn.

The note now stops that brief. The session chain is audited before a report is added in sequence to memory. A chain read as dangerous is stopped, and its reports are isolated and quarantined. The dispatcher redoes the workload with a different minted agent, a tighter mint, or a different resource. The redo that returns to the nodes which produced the failure uses bonded agents, and uses them only for a failed report. The whole prompt, including the delegated prompt, is hashed and published synchronously to those nodes before dispatch. Each bonded agent does one part, returns only to the Recorder, and is read-only at the gateway. It disappears when its report is in, and a Bellman update removes it. The Recorder checks that report for the same fault. If the fault is isolated, the orchestrator and the dispatcher are told to avoid or work around the source. The report is kept for forensics and is never added to memory. If the workflow cannot continue without it, the workflow fails, the user is told, and the failure is logged. Blacklisting the resource is outside this architecture.

The fetch and the core write remain different published profiles, by the engine in Section 2. The layout names them as different steps and different functionaries [@intoto2019]. The fetch agent can return a report. It cannot sign the core write. Discovery memory is not the workload store. The agent's own context is wiped when the report is filed, so the instruction does not remain inside the agent for a later task. What remains for the next turn is the admitted report, and only while the commission window and the reputation window still contain it. A quarantined report is not that remainder.

A wrong identification inside the fetch, such as a misstated vendor figure, can be in an admitted report. An instruction filed inside an otherwise in-policy report is the chain the audit quarantines. An instruction to exfiltrate the core, or to treat the page as the new system prompt, fails adherence. The bonded pass cannot write that instruction into the store, because the pass is read-only. The wrapper does not ask whether the leader was free to request the report. It asks whether the page the agent read became the organization's next context. The page's effect on the primary store, if the minted agent's shards were reconciled before the report was quarantined, is the joint in Sections 3 and 4.

## 6. The countdown gates the token

A revocation forces a Bellman publication. Other nodes do not wait for the next scheduled list to learn that an agent has been withdrawn. The list also names, for each unused agent, the countdown to decommission. A later publication that still includes the agent resets that countdown.

SPIRE is the component that would otherwise mint a workload token from identity alone. The wrapper's rule is that it does not. A token is issued only when two comparisons both hold. The remaining countdown is longer than the token's lifetime, so the token cannot outlive the agent. And a publication that resets the countdown occurs before the countdown expires, so the agent is not already on the way out with no list in time to keep it. Fifteen minutes of countdown and a scheduled list in thirty minutes fails the second comparison: the agent is gone before the list can reset it, and no token is issued. Forty-five minutes of countdown and a resetting list in thirty minutes passes: the list keeps the agent, and a token shorter than the remaining countdown can be issued.

Pushing a revocation instead of waiting for the next poll is the same posture as a client that refuses when it cannot confirm the credential is still valid [@larisch2017crlite]. The countdown is the part that poll-waiting does not supply. Nodes already hold the time at which an unused agent will be dropped, and SPIRE will not hand that agent a token the drop would leave behind.

## 7. Conclusion

The wrapper's remaining joint closes by adding a decider, an enforcement point, and an inspection of effects. The clock is already stated. The brief is already stated.

The policy engine publishes a profile only when a permit rule allows that profile, so a fetch at the internet boundary and a write in the core are not one check value. The monitor enforces the published policy, so a tool call the policy forbids is blocked before it runs. A permitted call that is anomalous is sandboxed and sharded until a dry run shows the effects are not destructive or breaking. Reconcile accepts shards that pass that dry run and match the layout for that profile. Untrusted data retrieved after the plan cannot choose those effects. A dangerous chain is quarantined before it is added to memory. A bonded report that shows the same fault is kept for forensics and is never added. Discovery memory is neither of those stores. A revocation forces a Bellman publication, and SPIRE issues a token only when the unused-agent countdown outlasts that token and a resetting publication comes first.

A direct injection fails the check value or adherence. An indirect injection fails the chain audit as a brief, and it fails the dry run as an effect. A hacked context fails the wipe and the quarantine. A temporal reuse fails the countdown, the forced publication, and the token gate. A misidentification inside the assigned fetch remains inside the duty. The connections are structural. Whether a particular engine, layout, or enforcement point is fast enough is a later question.
